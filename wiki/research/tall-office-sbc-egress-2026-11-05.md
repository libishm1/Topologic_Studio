# A tall office test model and the Saudi Building Code egress requirements (2026-11-05)

Date: 2026-11-05
Status: research note. No application code was changed. Follows [sbc-firefighting-future-notes-2026-11-05.md](sbc-firefighting-future-notes-2026-11-05.md), whose rule stands: no code value is used unless it was read from the code and cited by clause.
Models: kept locally with a sources file giving each one's origin and licence; not in the repository.

---

## 0. Summary

- **No openly licensed tall office IFC was found.** I looked for a model of 8 or more storeys with stairs, doors (ideally with exit flags) and IfcSpace rooms, under CC0, CC BY, MIT or an explicit free-use statement. Every tower or larger office candidate I found (Holter Tower, Energy Tower, the Rotterdam UpTown tower, Graphisoft's S-Office, Autodesk's advanced sample) has no stated licence or sits under vendor terms; their storey counts were not checked because they were not downloaded. The openly licensed office models top out at 4 to 5 storeys, and those are already in the corpus (TalTech DS3, Klassiqua, KIT Institute).
- **Two CC BY models were kept instead.** Both come from TU Wien's escape-route research: a real residential building in Vienna (7 storey levels, 32 doors flagged FireExit, occupant numbers and fire ratings on spaces and doors) and a fictional 5-storey mixed flats-and-offices test building. Neither is tall. They are the best open models found for testing the code checks themselves, because they carry the attributes the checks need.
- **The SBC text is not openly readable in English.** The official site (sbc.gov.sa) lists the 2024 edition. The Arabic "Code Provisions" of SBC 201 and SBC 801 are marked free but open only in a protected web viewer (view.protectedpdf.com) that needs a browser with JavaScript; I did not read it and did not try to extract from it. The English "Code Requirements" cost 550 SAR (SBC 201) and 500 SAR (SBC 801). Only the tables of contents are open PDFs.
- **SBC 201 is built on the IBC.** The ICC states that the 2018 SBC was "based on the 2015 International Codes". No official source I found names the edition behind the 2024 SBC, but its table of contents follows the IBC 2021 numbering (and not the 2015 or 2018 numbering), and a fire-protection vendor says SBC 801-2024 aligns with the IFC 2021. Every value below is therefore an **IBC 2021 value, to be confirmed against SBC 201**. None is an SBC value.
- **One value is known to differ between the two IBC editions behind the SBC:** the business occupant load factor is 100 sq ft gross per person in IBC 2015 and 150 in IBC 2018, 2021 and 2024. The SBC 2024 figure must be read before any occupant load is computed.

## 2. The Saudi Building Code: access and edition

**What the official site offers (checked 2026-11-05).** The building code page (https://www.sbc.gov.sa/En/BC/Pages/BuildingCode/BC.aspx?year=2024) lists the 2024 edition; the `year` parameter returns the same 2024 page for any year, and the 2018 page cited by the ICC (https://www.sbc.gov.sa/En/Feedback/Pages/SBC_2018.aspx) now returns 404. For each code it offers three versions:

| Code | Code Provisions (Arabic) | Code Requirements (English) | Code Commentaries |
|---|---|---|---|
| SBC 201, Saudi General Building Code | price 0, "Free"; Browse opens https://view.protectedpdf.com/qhxkte | 550 SAR, Add to Cart | 700 SAR |
| SBC 801, Saudi Fire Protection Code | price 0; https://view.protectedpdf.com/VV4dpX | 500 SAR | 650 SAR |

The free Arabic text opens in a protected PDF web viewer (a JavaScript application that serves no plain text to a non-browser client). I did not have a browser here, and extracting text from a protected viewer would defeat its protection, so I did not try. The open PDFs are the tables of contents: SBC201_CR_241224-FA.pdf (https://sbc.gov.sa/ar/BC/Documents/tableofcontent2024/SBC%20201/SBC201_CR_241224-FA.pdf) and SBC801_CR_241224-FA.pdf (same path, SBC%20801). They give section titles and page numbers only. **So no SBC clause value was read.** A person with a browser can read the Arabic SBC 201 for free; the English text needs a purchase.

**When the 2024 edition applies.** A market report quotes the National Committee: "the Saudi Building Code System 2024 will be mandatory starting from June 30, 2025", with the 2018 code applying to projects during a 180-day transition (https://sima-ksa.com/market-insight/update-of-the-saudi-building-code-system-2024). A fire-protection vendor gives "1st July 2025" (https://vortexfire.com/insights/sbc-201-801-2024-edition-the-key-changes-you-need-to-know). Neither is the committee's own text.

**Which IBC it adopts.**
- ICC country page (https://www.iccsafe.org/?p=240998): "The Saudi Building Code was revised in 2018 based on the 2015 International Codes by the Saudi Building Code National Committee."
- ICC-ES release of 15 June 2023 quoting the committee's general secretary (https://icc-es.org/wp-content/uploads/Saudi-Building-Code-National-Committee-and-ICC-ES-Enter-Memorandum-of-Understanding.pdf): "the Saudi Building Code, which uses the I-Codes as its base."
- For the 2024 edition I found no official statement. The evidence is its table of contents. SBC 201-CR-2024 chapter 10 runs "SECTION 1029 EGRESS COURTS", "SECTION 1030 ASSEMBLY", "SECTION 1031 EMERGENCY ESCAPE AND RESCUE", and chapter 4 ends with "SECTION 428 HIGHER EDUCATION LABORATORIES". In IBC 2015 and IBC 2018, Section 1029 is Assembly and 1030 Emergency Escape and Rescue (checked on the New Jersey IBC 2015 and 2018 texts at UpCodes); IBC 2021 and IBC 2024 have Egress Courts as 1029 (checked at UpCodes, Utah and New Jersey). SBC 801-CR-2024 chapter 10 runs to "SECTION 1032 MAINTENANCE OF THE MEANS OF EGRESS" (not compared with an IFC text here). The vendor above says the 2024 edition "aligns with ... International Fire Code (IFC) (2021 Edition)". I take IBC 2021 as the reference, with the caveat that the numbering alone cannot separate 2021 from 2024. For the values below I checked the New Jersey IBC 2024 text as well: the business factor, the capacity factors, the separation fractions, the dead-end lengths, the stair width and the exits-per-storey table are the same in 2024.
- The SBC section numbers in the table below are the titles in the official 2024 table of contents. Clause numbers inside those sections are assumed to follow the IBC and must be checked.

**Where the IBC text was read.** ICC's own code viewer (https://codes.iccsafe.org/content/IBC2021P2/chapter-10-means-of-egress) answered 403 to this machine and I did not work around it. I read the IBC 2021 text as adopted by Utah and New Jersey on UpCodes, checked UpCodes' amendment markup for every quoted section, and cross-checked against ICC's own publications (the 2021 Group A code-change monograph, which reprints the 2021 text, and ICC Interpretation 68-23). Utah deletes Section 1025 and 403.5.5 (luminous markings); those two were read from New Jersey, which does not amend them. No other quoted section is amended in either adoption.

## 4. How the app would measure each requirement

The app has a walkable lattice graph with stairs, the exits from IFC flags (`src/core/ifcSemantics.js`: FireExit, else IsExternal, else an EXTERNAL space boundary), door widths (`widthM` from OverallWidth), IfcSpace footprints and floor areas (`src/core/rooms.js`, `roomsFromSpaces`, `assignNodes`), cores for stairs and lifts (`src/core/cores.js`), multi-source walking distance to the nearest exit (`src/core/deadline.js`, `escapeDeadlines`) and distinct alternative routes with their shared length (`src/core/alternatives.js`, `alternativeRoutes`, `sharedShare`). Each check below says what it computes and what it needs from the IFC. The limits come from section 3 and stay "to be confirmed" until SBC 201 is read.

### 4.1 Occupant load
- **Computation.** Business occupant load per storey = gross floor area / factor. Gross area is the storey's area inside the exterior walls, including corridors, stairs and wall thickness (202), so summing IfcSpace areas undercounts it (rooms are net). Use, in order: `Qto_BuildingStoreyBaseQuantities.GrossFloorArea`, then the storey slab's outline, then the union of the storey's space footprints grown to the exterior wall line. Rooms the code treats differently (assembly rooms, storage, mechanical at 300 gross) need their own factor, so the space name or `Pset_SpaceCommon` occupancy fields decide the function per room, and the storey load is the sum.
- **IFC data needed.** IfcSpace with a usable name or `ObjectType`/`OccupancyType`; storey containment; a slab or quantity set for gross area. `Pset_SpaceOccupancyRequirements.OccupancyNumberPeak` (present in both TU Wien models) is the designer's number; the code allows an actual number only "where approved", so the check should report both.

### 4.2 Exit access travel distance
- **Computation.** `escapeDeadlines` already gives every node its walking distance to the nearest exit. For each room, take its worst node (the "most remote point") and compare with the limit. Vertical travel on exit access stairways counts; the graph's stair links approximate the code's line along the nosings.
- **The measuring point is the catch.** The code measures "to the entrance to an exit", and an exit includes an interior exit stairway (Section 202, "Exit"). On an upper storey the exit is the door into the protected stair, not a door to outside. The app's exit set today is the IFC's own flags plus external boundaries, which on an upper storey finds nothing or (in the TU Wien real-world model) also includes flat entrance doors flagged FireExit. The check needs an exit classifier: doors into stair enclosures (an IfcSpace around an IfcStair, a space named for the stair, or TU Wien's `ZDB_SpaceData.StaircaseType`), exterior doors at the level of exit discharge, and horizontal exits. Flagged doors that lead into a corridor stay exit access doorways.
- **IFC data needed.** Stair enclosure spaces or walls, door to space adjacency (space boundaries or the graph), and the sprinkler status (section 5).

### 4.3 Common path of egress travel
- **Computation.** For each node, the length of the route it shares with every route to a second, different exit before the two routes separate. `alternativeRoutes` with distinct ends and `sharedShare` measure exactly this overlap. A cheaper equivalent: run the nearest-exit field twice with the first exit removed per node, and find the branch point where the two shortest-path trees diverge. Report per room the worst value against 100 or 75 ft by the room's occupant load.
- **IFC data needed.** As 4.2, plus room occupant loads from 4.1.

### 4.4 Dead-end corridors
- **Computation.** Restrict the graph to corridor nodes. A dead end is a corridor branch from which the only way to an exit is back through its entry; its length is the graph distance from its far end to the junction where a second direction opens (the common path computed within the corridor). Exception 3 needs the corridor's least width: the lattice's distance-to-wall field along the branch gives it. Compare with 20 or 50 ft.
- **IFC data needed.** Corridor identification: space names (corridor, Gang, Flur), `ZDB_SpaceData.SpaceCategory` "Traffic area" in the TU Wien files, or IfcSpace `PredefinedType` where IFC4 exporters write it. Without it, dead ends can only be estimated from the graph's narrow passages.

### 4.5 Number of exits per space and per storey
- **Computation.** Per space: count distinct exit access doorways (graph doors between the room and the rest) and compare with the load and common-path rule. Per storey: count separate exits reachable on that storey (stair enclosure entrances and exterior exits, scissor stairs counted once) against Table 1006.3.3 for the storey load, and check the count is kept down to discharge (a stair that ends at an upper floor does not count below).
- **IFC data needed.** The exit classifier of 4.2, storey containment, stair to storey span (cores.js stacks).

### 4.6 Exit separation and stair remoteness
- **Computation.** The overall diagonal is the largest distance between two points of the storey outline (the diameter of its convex hull). Take the two exits farthest apart and compare their straight-line distance (to any point of the door width, or the closest riser) with 1/2 or 1/3 of it. For high-rises, measure between the nearest points of two stair enclosures against the lesser of 30 ft and 1/4 of the diagonal.
- **IFC data needed.** Storey outline (slabs or spaces), door positions, stair enclosure geometry.

### 4.7 Egress capacity and minimum widths
- **Computation.** Required stair capacity per storey = that storey's load times 0.3 (or 0.2) in, not summed over storeys; other components = load served times 0.2 (or 0.15) in. Provided width: doors from IFC (see below), corridors from the lattice clearance field along each corridor, stairs from the stair mesh width or a stair Pset. Then the 50 percent rule (1005.5): remove each exit in turn and check the rest still give half the required capacity. Minimum widths are direct comparisons: doors 32 in clear, corridors 44 in (36 in under 50 occupants), stairs 44 in (36 in).
- **IFC data needed.** OverallWidth is the leaf or frame width, not the code's clear width between door face and stop, so the check must either subtract a stated allowance (a modelling choice, to be labelled as such) or measure the opening from geometry. Stair width is rarely a property; the TU Wien models give risers and treads but not width, so stair width comes from geometry.

### 4.8 High-rise provisions
- **Computation.** High-rise if any occupied storey's floor is more than 75 ft above the fire department access level. Storey elevations give the height; the access level is not in the IFC, so take the lowest storey with exterior exits as a default the user must confirm. Then: stair count against 403.5.2 only above 420 ft; stair remoteness (4.6); lift count against 403.6.1 when an occupied floor is above 120 ft (IfcTransportElement ELEVATOR, or lift-named spaces); smokeproof enclosures and luminous markings are reported as "cannot tell" unless the model says so (TU Wien's `AirPressurization` on spaces is one such signal).

## 5. What cannot be checked from a typical IFC

- **Sprinkler and alarm status.** The limits switch on "equipped throughout with an automatic sprinkler system in accordance with Section 903.3.1.1" and, for the capacity factors, an emergency voice/alarm system to 907.5.2.2. Sprinkler heads (IfcFireSuppressionTerminal SPRINKLER) are rarely in architectural models and cannot show compliance with a standard; TU Wien's `SprinklerProtection` is a per-space claim. This must be a user input.
- **Occupancy classification.** Group B versus A-3 for large meeting rooms, accessory uses, mixed-occupancy separation. Space names give a guess; the classification is the designer's.
- **Fire department vehicle access level**, which fixes the high-rise threshold; it is site information.
- **What is an exit in code terms.** Whether a stair is an enclosed interior exit stairway (Section 1023, rated enclosure) or an open exit access stairway; whether a door is a horizontal exit. FireRating labels sometimes exist (TU Wien: EI 30, REI 60) but in European classes, not IBC hours.
- **Door clear width, swing direction, hardware.** Clear width differs from OverallWidth; swing direction (1010.1.2) needs the opening direction and handing; panic hardware, locking and door closers are not modelled.
- **Smokeproof enclosures, pressurization, luminous markings, exit signs, emergency lighting**: usually absent.
- **Accessible means of egress, areas of refuge**, and stairway width "between handrails" (handrails are rarely modelled to the needed accuracy).
- **Exit discharge and the public way**: outside the building model.
- **Actual furniture layout** for the "natural and unobstructed path": present in some models, absent in most, and movable furniture is a judgement.
- **The SBC's own changes to the IBC values**, which no IFC can supply: they need the SBC 201 text.
