### Where the previous handoff's plan landed

[next-line-status-2026-08-23.md](next-line-status-2026-08-23.md).

The two findings that changed the plan:

- **TopologicPy is LGPL-3.0-or-later, not AGPL.** Verified on PyPI. The

  apply.
- **`Graph.ShortestPath` does not scale here.** 1.44 s per query on a 2,650-node
  graph versus 14 ms for a native A*, with identical results. The roadmap
  proposed migrating all pathfinding onto TopologicPy; that would have made the
  app unusable. It is now an opt-in engine behind a fast default.

## 4. Architecture

```
IFC file
  │
  ├─ SHA-256 hash ───────────► IndexedDB fragment cache     lib/fragmentCache.js
  │                                 │ hit → no IFC parse at all
  ├─ IfcLoader.load ◄─── miss ──────┘                       viewer/ViewerManager.js
  │
  ├─ getItemsOfCategories() ─► floor / stair / door / wall ids   viewer/categories.js
  ├─ getItemsGeometry()     ─► transferable typed arrays
  │
  ├─ Web Worker ────────────► walkable points + wall lines  workers/sampler.worker.js
  │
  └─ POST /api/ifc/graph ───► NavGraph (numpy + cKDTree)    services/graph_builder.py
                                  ├─ POST /api/ifc/path     graphs/pathfinding.py
                                  ├─ GET  /api/fire/stream  graphs/fire.py
                                  └─ POST /api/rl/train     graphs/rl.py
```

The load-bearing idea: **the browser already holds the geometry in order to draw
it**, so it samples walkable points there and uploads only the point cloud.
Classic shipped every triangle to Python and resampled server-side.

### Backend modules

```
app/
├── main.py              app factory, /health, /api/capabilities
├── config.py            env-driven settings
├── models.py            request/response schemas
├── store.py             NavGraph + LRU/TTL GraphStore
├── perf.py              timing markers
├── geometry/            common, sampling, adjacency, obstacles
├── graphs/              pathfinding, topologic_engine, fire, rl
├── routers/             ifc.py, simulation.py
└── legacy/              contract.py (moved verbatim), helpers.py
```

`legacy/contract.py` is the only file carried across unchanged. It is the
`/upload-topology` and `/upload-ifc` workflow. It has not been re-profiled or
re-tested beyond "it still imports and returns 200". Treat it as unknown
territory.

### API

Next: `/api/ifc/graph`, `/api/ifc/graph/{id}` (GET, DELETE), `/api/graphs`,
`/api/ifc/path`, `/api/ifc/path/compare`, `/api/fire/timeline`,
`/api/fire/stream`, `/api/rl/train`, `/api/capabilities`, `/health`.

Classic compatibility, unchanged contracts: `/ifc-egress-graph`,
`/ifc-egress-path`, `/graph-meta`, `/upload-topology`, `/upload-ifc`.
The Classic frontend can point at this backend, which is what makes an A/B
comparison on one machine possible.

Graph node and edge arrays come back base64 `float32`/`uint32`, not JSON
numbers — about a sixth of the bytes and no per-number parse.

## 7. Traps a follow-on agent will hit

These all cost me time. Do not re-litigate them.

1. **Do not set COOP/COEP headers on the dev server.** Cross-origin isolation
   makes web-ifc select its pthread build, which spawns workers with an
   undefined script URL. Every worker fetches `/undefined`, gets `index.html`,
   and dies on `Unexpected token '<'`. IFC loading never completes. There is a
   comment in `vite.config.js` saying so.

2. **`FragmentsManager.getWorker()` downloads from unpkg.com.** It is not a
   local resolution. `scripts/sync-assets.mjs` copies the matching worker into
   `public/fragments/` on postinstall; `ViewerManager.resolveWorkerUrl()`
   prefers that and only falls back to the CDN.

3. **Walkable sampling requires an upward-facing normal.** Using
   `abs(normal_up)` samples slab undersides and ceilings, producing two point
   sheets per storey that the neighbour search braces into a space-frame truss.
   56% of edges were bracing before this was fixed.

4. **Do not use `THREE.Line` for anything that must be seen.**
   `LineBasicMaterial.linewidth` is ignored by every major browser. Routes are
   `TubeGeometry`.

5. **Vite binds `localhost` (::1), not `127.0.0.1`.**

6. **A radius-only neighbour query explodes edge count.** 0.5 m sampling inside
   a 2.25 m radius gives ~56 edges/node. `max_degree` caps it at 12.

7. **`git worktree`, not a copy.** Do not `git init` in `TopologicStudio-Next`.

8. **The Classic checkout has 22 pre-existing uncommitted files.** They are not
   mine and not in the tag. Do not commit them; do not discard them.

## 8. Open decisions for the human

None of these are code problems. They need a research or product call.

1. **Door waypoints.** One navigation node per door opening (was one per mesh:
   14 doors made 44 nodes). Right for routing. Possibly too coarse for egress
   *capacity*, where a wide double door might warrant more than one node.

2. **Silent pick snapping.** Clicking in the model snaps the marker to the
   nearest graph node, because a ray hits whatever surface faces the camera —
   usually an exterior wall. Click a roof and the marker jumps somewhere you did
   not click, with no warning. Warn above a distance threshold, refuse the pick,
   or leave it?

3. **The unreachable 5.8%.** On the Duplex, 1,663 of 1,765 nodes form one
   network; 102 sit in 12 isolated pockets on an up-facing surface 0.5 m below
   the first floor. Is that real walkable area the model fails to bridge with a
   step, or geometry that should not be walkable at all? The graph is not pruned
   because unreachable floor area is meaningful egress information.

4. **Merge or keep separate.** Nothing here touches Classic. When you want it:
   `cd TopologicStudio && git merge next/studio-2`. The backend `app/` package
   is replaced wholesale — review `legacy/contract.py` first, it is the only
   verbatim carry-over.

### Not verified

- **One model, one browser, one machine.** Chrome 151 on Windows, Duplex only.
  No Firefox, no Safari, no large or dirty models, no IFC4.
- **No CI.** Nothing runs these suites automatically.
- **No human has used the app.** Every interaction so far was scripted.
- **`/upload-topology` and `/upload-ifc`** are carried over unchanged and
  unprofiled. The Topology JSON viewer renders its placeholder in tests; nobody
  has loaded an actual TopologicPy JSON export through it.
- **Nothing is deployed.** `render.yaml` for the Next backend exists with
  `autoDeploy: false`. The GitHub Pages workflow has not been pointed at this
  line.
- **Ghost mode** mutates fragments materials directly. If That Open reassigns
  materials on LOD transitions the ghost may not persist. Not observed, not
  proven absent.
- **Upward-only sampling** assumes trustworthy face winding. A model with
  *partly* inverted winding silently loses walkable area — the Reachable % stat
  is the signal to watch. The fallback only catches a model with no upward faces
  at all.

## 10. Suggested next work

Roughly in order of value.

1. **Have a human drive it.** Load a model you know well and check the routes
   are plausible. Everything below is less important than this.
2. **A second and third IFC model.** Ideally IFC4, and something larger than
   2 MB. The sampling and connectivity heuristics are tuned against one
   building.
3. **Wire the suites into CI.** `pytest`, `npm run lint`, `npm run build` are
   easy. The browser suite needs a runner with Chrome.
4. **Deploy the Next backend** to its own Render service and point a preview
   frontend at it. Keep Classic's service untouched.
5. **Profile `/upload-ifc`.** It is the last unexamined path.
6. **Slim the `thatopen` chunk** (5.4 MB, 911 KB gzipped). It is lazy-loaded, so
   this is polish, not urgent.
7. **`Graph.ByIFCFile` as a separate feature.** TopologicPy 0.9 can build a
   topological *relationship* graph straight from IFC. That is a different
   object from a walkable lattice, so it does not replace the egress pipeline,
   but it would make a genuinely new "IFC relationship explorer" view.
8. **Fix `tools/bench_egress.py` wall double-count** on IFC2X3
   (`by_type("IfcWall")` already includes `IfcWallStandardCase`). Benchmark
   payload only; the Classic-vs-Next comparison is unaffected.

## 11. Operating notes

- Follow [wiki/CLAUDE.md](../CLAUDE.md) for any browser testing: capture console
  evidence, classify findings, update `wiki/issues/` **before** replying, and
  stop for a human on visual, safety or research-validity calls.
- Prefer measuring to guessing. Every real bug in this session was found by
  instrumenting and reading numbers, and two of my first diagnoses were wrong
  until I did (the graph was not misplaced, it was occluded; picking was not
  broken, my harness was on the wrong tab).
- Keep Classic demo-safe. If forced to choose between clean architecture and
  Classic still working, Classic wins.
- The perf markers are deliberately shipped, not dev-only. `VITE_PERF_LOG=1` and
  `PERF_LOG=1`.
